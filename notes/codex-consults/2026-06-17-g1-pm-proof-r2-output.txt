`closure(acd ∪ bcd)`,

which contains all vertices of `t` and all edges except `ab`. So the only possible extra intersections are:

1. the tetrahedron `abcd` itself: doubled tet, your (A)
2. one of the non-glue triangles `abc`, `abd`: your (B)
3. the missing edge `ab`: your (C)

There is no separate vertex-only obstruction in this two-face setup, because all four vertices already lie in the intended glue disk.

For (C): nothing forces `ab` to be absent from `M - t` merely because `ab` is a boundary edge after adding `t`. It can already occur elsewhere as an interior edge of `M - t`, with link a cycle not involving `c` or `d`. Then adding `t` contributes the edge `cd` to `Lk(ab)`, giving

`Lk_M(ab) = old cycle ⊔ edge(cd)`,

so the edge link is disconnected. No triangle has become triply incident, and no tetrahedron is doubled. So (A) and (B) do not cover it.

Your deletion argument is basically right, with one precision: deletion cannot create new paths in a link, but it can delete an entire bad component if the deleted tet touches that edge. So the clean resource statement is: choose an eligible `u` disjoint from `t`; then `u` does not contain `a` or `b`, hence does not affect `Lk(ab)`. Thus `M - u` still has disconnected `Lk(ab)`, contradicting stickerball/genuine ball. So (C) only needs a disjoint pair, not the `maxdeg >= 4` count.

The needed lemma is genuinely edge-level:

`stickerball => every edge link is connected`
more sharply, in a genuine 3-ball:
`Lk(e)` is an interval for boundary edges and a cycle for interior edges.

On the Lean-definition point: your diagnosis is correct. A `GlueStep` that only tracks tetra face intersection with the boundary and updates boundary by symmetric difference does not see rogue lower-dimensional intersections like `ab`. It therefore does not enforce classical shelling cleanliness. You need one of:

- strengthen `GlueStep` to require full subcomplex intersection:
  `K ∩ closure(t) = closure(glueFaces)`, or
- carry enough manifold/link invariants, including connected edge links, to rule out (C).

The classical escape hatch does not remove the obligation. Classical shellability uses subcomplex intersection purity/cleanliness, not just face-count bookkeeping. If your formal definition is weaker, then “shellable + triangle pseudomanifold” will not automatically rule out (C).
